# 可见的 API 自动化与双击入口

用户批准设计方案后、编写项目自动化代码前阅读。这里提供通用约束，不携带任何机构的固定参数，也不自动适配不同 SolidWorks 版本。

## 连接与环境

- 使用用户明确选定的版本。先读取该版本的安装位置、可用模板和 API 文档/类型库，不硬编码其他项目的磁盘路径或模板名称。
- SolidWorks 必须有可见窗口。已有实例时绑定明确的目标实例；没有实例时只启动一次并等待就绪。多个实例造成绑定歧义时先识别或请用户指定，不连续创建隐藏实例试错。
- 不擅自关闭用户的进程或文档。恢复失败构建时，只处理能够证明属于当前任务的文档和输出。
- 优先使用已验证的动态 COM 调用。某些环境中 PowerShell/.NET 的 COM 类型信息查询会失败；可由 PowerShell 负责启动和文件编排，由 Python 的后期绑定 COM 或 VBScript 执行 SolidWorks 调用。版本读取和可见窗口检查也必须测试，不能只验证建模代码。
- 不使用 Computer Use、SendKeys、鼠标模拟或以截图坐标驱动操作。通过 CAD API 导出预览图片并人工目视核对可以使用。

## 几何、引用与数据类型

- 将项目参数集中管理并绑定批准的设计汇总。SolidWorks API 长度使用米，角度通常使用弧度；在明确边界转换单位，不多次重复缩放。
- 按特征类型、几何属性或持久引用识别基准，不假设所有模板的基准面都使用同一种语言名称。可创建稳定的项目基准名。
- 特征选择、实体映射和配合引用应有断言或检查结果；选择失败不能继续创建看似成功但引用错误的配合。
- 严格匹配目标 API 的参数类型。Python COM 传数值数组时，在要求双精度数组的接口使用 `VARIANT(VT_ARRAY | VT_R8, values)`，例如数学变换和外观数组；不要把 Variant 元素数组默认视为 double 数组。按接口定义使用 ByRef 错误参数。
- 使用动态 COM 时，某些无参数成员表现为属性，另一些表现为方法；检查实际暴露方式。不要因为返回的 COM 对象“可调用”就调用其默认成员。必要时依据本地类型库明确指定调用方式。
- 不把所有 API 返回值都按“0 成功”解释；读取目标版本对应的枚举。`ForceRebuild3(False)` 返回 True 表示重建成功。保存后核对实际文件和重新打开结果，不只依靠历史案例的保存返回值假设。
- 强制重建或修改拓扑后，重新获取需要测量的实体/面代理，避免继续使用过期 COM 引用。
- 初始变换必须说明坐标系、旋转和轴向方向；负向距离、翻转端盖及实例名称要读取结果确认，不以初始摆放代替约束后的实际位置。

## 生成项目自动化包

生成项目专用、可复现的构建代码，不将整套案例文件原样作为通用脚本。可采用 VBS 双击入口、PowerShell 编排及 Python/VBScript 建模模块，选择运行环境已支持的组合。

入口要求：

1. 以脚本所在目录定位依赖，对包含空格和中文的路径正确加引号；不能依赖 Explorer 启动时的工作目录。
2. 检查依赖、用户选定的 SolidWorks 版本、模板和可见 COM 连接。缺少依赖时说明缺少什么，不静默安装不相关软件。
3. 为每次完整运行创建独立输出目录，记录本次目录位置。标准件优先从随包的已核实缓存导入。
4. 调用零件生成、标准件导入、装配、外观及静态验证模块。每个子进程结束后检查退出码，再进入依赖步骤。
5. 报错时保留当前输出，记录阶段、实际异常、控制台输出和日志路径。VBS 最终失败提示不能仅显示一个退出码。
6. 成功标记只能在必要步骤完成并验证文件后写入。干涉报告可存在于成功交付中，不能因为其非零而让脚本自动重建几何或伪报技术失败。

允许任务内断点续建来修复错误，但最终完整入口验证必须使用新目录，真实执行构建步骤。不能通过复制已存在的成品模型来宣称自动建模已经从头跑通；标准件缓存复用是正常输入。

参数化脚本如有恢复模式、仅外观模式或仅打开模式，必须在文档中与“完整自动构建”区分。用户需要的双击入口应有清晰文件名，说明依赖文件需保持在一起。

## 版本范围

针对当前选定版本核对调用，不自动探测多个版本后择一建模。用户以后要求另一版本时，重新询问缺失版本信息并按该次明确版本检查环境；不要承诺未经测试的跨版本兼容性。
