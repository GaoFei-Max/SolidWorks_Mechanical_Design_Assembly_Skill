# 静态检查与完整入口验证

在规划验收和交付前阅读。检查模型是否正确输出，同时保留用户允许的干涉结果；默认不进行运动联动测试或运动仿真。

## CAD 检查

根据本项目批准方案确定预期数量，不写死任何案例的零件或配合数量。

|项目|应记录的证据|
|---|---|
|原生文件|每种零件、总装和必要子装配文件存在且非空；引用指向随包零件|
|零件|实体数、有效实体、强制重建结果、特征错误、关键接口尺寸|
|组件|实例数、对应源文件、位置/方向、解析及抑制状态|
|配合|实际原生配合的类型、引用组件和实体、距离或角度、错误状态|
|外观|零件和总装保存状态；外观与物理材料状态分开|
|预览|CAD API 输出的整体及必要内部视图，目视检查方向、可见性和主要结构|

允许设计所需的旋转、滑动等剩余自由度。基础件固定和合理约束符合预期即可，不把“全部固定”或“全部完全约束”当作通用通过标准。

## 干涉报告策略

执行最终静态姿态的一次干涉检测，记录检测设置及以下结果：

- 涉及组件实例、可定位的面/位置或预览、干涉体积（API 可提供时）与单位。
- 是否把重合接触面算作干涉、是否检查隐藏/抑制组件、是否包含标准件内部多实体之间的干涉。
- 如有明显的名义配合、过盈设计或供应商简化几何因素，可解释可能原因；没有依据时不擅自标为正常。

检测结果分三种：已检查无干涉、已检查有干涉、检测未完成。第三种不得写成前两种。无需为获得体积字段调用猜测的 API；不可获取的字段明确说明。

已检测到干涉仍可交付全部文件，标记“已完成，存在静态干涉”并附结果；不要重复生成零件、改变中心距、缩放标准件或反复重建以清零。用户明确要求处理某处干涉时，再针对该处开展修改并复查。

干涉检测 API 崩溃、未生成文件、重建失败、配合引用丢失和脚本异常属于技术问题，与“检测成功且存在干涉”不同。对技术问题进行有依据的局部修复，不把它们隐去；确实无法完成时保留可用输出并说明未通过的步骤。

## 从真实入口完整跑通

1. 使用交付的 VBS 入口，从新的输出目录开始。可以用 `cscript` 运行同一 VBS 来捕获退出码；若有 quiet 参数，只能关闭最后提示框，不能跳过构建或验证。
2. 实际经历环境检查、标准件缓存导入/获取、自制件生成、原生装配、外观保存与静态检查。测试过程中保持 SolidWorks 可见，不绕开入口直接调用已经验证过的单个模块。
3. 验证最终退出码、成功标记、本次日志和本次生成的原生文件一致。不能用上次运行留下的通过文件判断本次成功。
4. 保存并重新打开本次总装，确认依赖可解析、文件版本正确、主要组件和外观存在。只关闭本次任务创建的文档。
5. 若发生脚本错误，读实际日志定位、修复并重新验证完整入口；重复同一失败时改变诊断方式，不盲目重启多个实例。用户取消某项测试后遵从其范围变更，交付时如实标明未验证项目。

保存简洁的入口验证记录：入口文件和启动方式、输出目录、SolidWorks 版本、可见窗口证据、执行结果、零件与实例数量、配合数量、干涉检测状态、日志位置及未验证项。只有真实跑通后才能写“完整自动构建已验证”。

## 交付内容

- 独立 `.SLDPRT`、主 `.SLDASM` 和实际需要的子装配；重复实例复用同规格零件。
- 双击 VBS 入口及必要的 PowerShell/Python/VBScript 模块、参数、标准件缓存和来源记录。
- 批准的设计汇总、尺寸来源与计算、简化项、材料/公差/校核状态。
- CAD 静态检查和干涉报告、完整入口验证记录、可读的运行日志、整体和必要内部预览。

打包时保持相对目录和原生文件引用完整，排除锁文件、运行缓存及无关调试产物。不要只发送 VBS 而遗漏它依赖的脚本和标准件。用户另有文件清单时按其范围输出。

最终答复给出文件链接、如何双击运行、关键通过项以及干涉或未验证项。不要以“零干涉”“运动正常”“可直接制造”等未经验证结论替代检查记录。没有要求录像、工程图或运动仿真时，不把它们作为交付前置条件。
